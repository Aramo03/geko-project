## 1. Lead (зона `lead`)

**Задание:** порядок мержа `User → Language → Category → … → UIBlock`; таблица мержей; ревью; никто не в `main`; после мержа — рабочие `makemigrations` + `migrate`.

### Не сделано / сделано плохо

1. **Мердж в `main/models.py` без финальной зачистки**
   - В начале файла остались **два определения `Language`** (строки ~4–8 и ~32–37).
   - Между ними — старый блок TODO в тройных кавычках и **повторный** `from django.db import models` не нужен, но дубликат класса — следствие нерешённого конфликта.
   - При запуске: `RuntimeWarning: Model 'main.language' was already registered`.

2. **Мердж миграции `main` сломан**
   - В [`0001_initial.py`](backend/apps/main/migrations/0001_initial.py) в операции `TeamTranslation` после `options={...}` торчат лишние строки (`('name', models.CharField(max_length=100))`, `],`) — типичный **незакрытый merge conflict**.
   - Итог: **SyntaxError**, миграции не импортируются → **`migrate` на чистой БД невозможен** (DoD зоны 10 и Lead не выполнен).

3. **Две шапки генерации в одной миграции**
   - `# Generated by Django 6.0.7` и `# Generated by Django 5.1.6` в одном файле при [`requirements.txt`](backend/requirements.txt) `Django==5.1.6` — признак того, что **две ветки правили одну миграцию** без единого финального `makemigrations` на обновлённом `dev`.

4. **Порядок мержа User первым не соблюдён по факту**
   - Daniel не внёс кастомный `User`, но в репозитории есть [`accounts/migrations/0001_initial.py`](backend/apps/accounts/migrations/0001_initial.py) под стандартный `AbstractUser` (username). Это блокирует последующую нормальную реализацию email/role без новой миграции и согласования с Lead.

5. **DoD Lead:** «после полного мержа команда запускает migrate» — **не проверено**; pipeline не запускает `migrate`, только `check`.

### Что должен был сделать Lead

- Не оставлять маркеров конфликта в `models.py` и миграциях.
- После последнего PR — один человек (часто зона 10) + Lead: **чистая БД → `migrate` → зафиксировать в чате**.
- Добавить в CI (или чеклист PR): `python manage.py migrate` на SQLite.
